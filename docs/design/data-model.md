# 状態と永続化

[DESIGN.md](../../DESIGN.md) から分割した詳細。

## 状態と永続化

項目の状態読み込みと設定・実行結果は`MaintenanceItemLog`で項目ID・日本語の項目名・操作・原因を記録する。例外やタイムアウトだけでなく、例外なしの状態不明、Failed/Partialの詳細、受付拒否も対象とする。状態取得の技術的な原因は`StateFailureReason`で共通境界へ渡し、理由が未提供ならその旨を明記する。共有MMAgent照会は原因を結果と一緒に保持し、後続の再試行で元の照会の原因を失わない。クリーンアップと未接続デバイス画面にも同じ診断方針を適用する。原因の要約は秘密値と制御文字を除き、記録量を制限する。

- `%APPDATA%\Lumin4ti\settings.json`: 言語、自動更新確認、除外パスなどの利用者設定。クリーンアップの設定は`Cleanup`に持ち、外した規則の上書き、除外4種、カスタムフォルダー、高度なクリーンのパターン選択、安全な削除と復元ポイントの設定、累計と前回の実績を保存する。更新で規則が増えても選択が無効化されないよう、有効なものではなく外したものだけを記録する。旧`CleanupExclusions`は旧カードと旧版への戻しのため残し、旧設定の予約項目は無視され次の保存で消える。
- `%LOCALAPPDATA%\Lumin4ti\logs\`: 起動、操作、例外、移行の診断ログ。旧インストール先を回収するときも保持する。
- `%ProgramData%\Lumin4ti\backups\`: Pathなどデータ書き換えの保護バックアップと起動時再試行のキュー。旧版が置いたタスク登録用XMLは旧タスクの移行で削除する。AdministratorsとSYSTEMだけが変更できるACLを検証する。旧設定切り替え用の退避も残るが、新しいトグルから参照しない。

Windowsでは`LoggerBootstrap.Initialize()`がログ構成前に、旧`%APPDATA%\Lumin4ti\logs`と`%LOCALAPPDATA%\Kagayoi\Lumin4ti\logs`から現行ログ保存先へ移行する。`LegacyLogMigration`は直下の既知ログ（日付形式の`Lumin4ti_*.log`と`msi-per-machine.log`）だけを一意な`legacy-<GUID>-`接頭辞付きで移し、既存ログや他の利用者ファイルを上書きしない。パス要素とファイルの再解析ポイントは辿らず、使用中・競合・別ボリュームなどで移動できないログは元に残して次回起動で再試行する。移行失敗は起動を妨げず、移行元ログフォルダーと旧Kagayoi配下のアプリフォルダーは空の場合だけ除去する。

設定保存は一時ファイルからの置換で行い、保存要求を直列化する。既存設定の読込に失敗した場合は既定値でUIを起動するが、壊れた原本を既定値で上書きしない。設定画面とクリーンアップの選択保存は保存例外と原本保護による保存抑止を利用者へ表示し、画面へ反映された一時的な変更と保存済みの設定を区別する。

ON/OFFの設定切り替えとDefenderの既定設定へのリセットは永続バックアップを作成・参照しない。OFFは各RegistryToggleSpecの解除値（nullなら値の削除）へ設定し、適用前の元値には戻さない。HKLMの変更はマシン全体に作用し、CEIPのようなHKLM/HKCU混在項目でも利用者ごとの共有所有者管理は行わない。ある利用者のOFFは共有HKLM値を解除するが、他利用者のHKCUは変更しない。

VBS/HVCIのONはBCDとレジストリ3値の無効化、OFFはその明示設定の削除。実効状態はOS・ポリシー・再起動に依存し、OFFで保護機能が必ず有効になるとは保証しない。UWPバックグラウンド実行はトグルではなく一括設定として扱い、毎回インストール済み対象を再列挙する。「一括OFF」はDisabled/DisabledByUserを両方1、「一括ON」は両方0にする明示的な許可であり、値の削除やWindows既定への復帰ではない。アプリ追加後も同じボタンを続けて実行できる。Windowsのポリシーやアプリ側の制約まで解除するものではない。旧バックアップは読み込み・移行・削除しない。

UWPの対象は現在の利用者のパッケージから、framework・resource・bundleを除外し、固定の`AppxManifest.xml`のApplicationとExtensionの起動属性で判定する。背景タスク専用のUWPも含め、起動属性のないデータ・コーデック宣言やデスクトップ専用アプリ、Windows 8/8.1形式は対象外とする。manifestを読み取れない場合や未知・矛盾した起動属性は、パッケージ名と原因を示して全対象の書込前に中止する。対象外と判定できる宣言と判定不能を区別し、関係のないパッケージの存在だけで一括設定を失敗させない。

操作途中の失敗・キャンセルへの補償は、直前の型付き実値をメモリにだけ保持して行う。書込み後と補償後に再照合し、補償不能・外部変更・部分失敗をログと結果へ表示する。プロセス強制終了後の復元は保証しない。Defenderリセットは既存の改ざん防止・サービス確認・変更後検証を維持し、途中失敗では変更が一部残る可能性を明示する。

Pathとクイックアクセスの並べ替えはデータ書き換えとして従来の保護バックアップを維持する。ProtectedBackupStorageのACL・所有者・再解析ポイント検証は、これらのデータとタスク登録用XML・移行保留情報にも引き続き適用する。危険な保存領域を検出した場合は従来どおりfail closedにする。

クイックアクセスの並べ替えは、Shell名前空間を開けないピン留め（削除済みドライブ、アンインストール済みのクラウドドライブなど）を外さない。外すと付け直せず利用者のピン留めを失うため、元の相対順のまま先頭へ残し、開ける項目だけを昇順で付け直す。スキップ判定と変更後の実状態検証は「残した項目＋並べ替えた項目」を期待値とし、残した項目があれば成功ではなく部分成功として対象パスを表示する。

通常のファイル列挙・属性変更・削除・失敗時の属性復元は、再解析を拒否して取得した同一ハンドルを使う。`NativeCleanupEntry`が`NtCreateFile`の`OBJ_DONT_REPARSE`と最終要素の属性確認を集約し、ディレクトリの一覧もハンドルから取得する。パスを再解決して削除する代替経路へ戻さず、検証不能な対象は保持して診断へ含める。

クリーンアップの規則・SQLite・INI・実行中の製品の扱いと走査結果の世代失効は[cleanup-design.md](cleanup-design.md)にまとめる。ファイル整理は通常のローカルドライブを対象とする。DOSドライブ名はデバイス名へ一度解決して操作中固定し、UNC・SUBSTなど安全な解決を実装していないマッピングは拒否する。起動時の再試行は下記の保護キューを使い、後で名前だけを再解決する MoveFileEx 方式は使わない。

リンク保護は対象確認時点と削除直前のハンドル属性を基準とする。確認時点のリンクは保持し、途中でパスが差し替えられても同一ハンドルからリンク先へ作用しない。最終確認の後に別プロセスが同じオブジェクトをリンクへ変える競合については、リンク自身の残存までは原子的に保証しない。この境界で通常のキャッシュ削除とリンク先の実体保護を両立する。

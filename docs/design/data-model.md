# 状態と永続化

[DESIGN.md](../../DESIGN.md) から分割した詳細。

## 診断と保存先

項目の状態読み込みと設定・実行結果は`MaintenanceItemLog`で項目ID・日本語の項目名・操作・原因を記録する。例外やタイムアウトだけでなく、例外なしの状態不明、Failed/Partialの詳細、受付拒否も対象とする。技術的な原因は`StateFailureReason`で共通境界へ渡し、未提供ならその旨を明記する。共有MMAgent照会は原因を結果と一緒に保持する。クリーンアップと未接続デバイス画面にも同じ方針を適用し、原因の要約は秘密値と制御文字を除き、記録量を制限する。

- `%APPDATA%\Lumin4ti\settings.json`: 言語、自動更新確認、除外パスなどの利用者設定。クリーンアップの設定は`Cleanup`に持ち、外した規則の上書き、除外4種、カスタムフォルダー、高度なクリーンのパターン選択、安全な削除と復元ポイントの設定、累計と前回の実績を保存する。有効なものではなく外したものだけを記録するため、更新で規則が増えても選択は無効化されない。旧`CleanupExclusions`は旧版への戻しのため残し、旧設定の予約項目は無視され次の保存で消える。
- `%LOCALAPPDATA%\Lumin4ti\logs\`: 起動、操作、例外、移行の診断ログ。旧インストール先を回収するときも保持する。
- `%ProgramData%\Lumin4ti\backups\`: Pathなどデータ書き換えの保護バックアップと起動時再試行のキュー。AdministratorsとSYSTEMだけが変更できるACLを検証する。レジストリタブの削除前バックアップは`registry\<UTC時刻>-<GUID>.json`（型付きJSON。版・SID・ハイブ（HKLM・利用者・利用者の Classes）・表示・キーパス・値の名前・型・元バイト列・カテゴリーを持つ）と`<id>.result.json`で、自動削除せず、一覧から復元する（[registry-cleaner.md](registry-cleaner.md)）。旧版が置いたタスク登録用XMLは旧タスクの移行で削除する。

## ログ移行と設定保存

`LoggerBootstrap.Initialize()`がログ構成前に、旧`%APPDATA%\Lumin4ti\logs`と`%LOCALAPPDATA%\Kagayoi\Lumin4ti\logs`から現行の保存先へ移行する。`LegacyLogMigration`は直下の既知ログ（日付形式の`Lumin4ti_*.log`と`msi-per-machine.log`）だけを一意な`legacy-<GUID>-`接頭辞付きで移し、既存ログや他の利用者ファイルを上書きしない。再解析ポイントは辿らず、使用中・競合・別ボリュームなどで移せないログは元に残して次回起動で再試行する。失敗は起動を妨げず、移行元と旧Kagayoi配下のアプリフォルダーは空の場合だけ除去する。

設定保存は一時ファイルからの置換で行い、保存要求を直列化する。既存設定の読込に失敗した場合は既定値でUIを起動するが、壊れた原本を既定値で上書きしない。設定画面とクリーンアップの選択保存は保存例外と原本保護による保存抑止を利用者へ表示し、画面上の一時的な変更と保存済みの設定を区別する。

ON/OFF設定・VBS/HVCI・UWP一括設定・操作途中の補償は [toggle-and-uwp-settings.md](toggle-and-uwp-settings.md) にまとめる。

## 保護バックアップと並べ替え

Pathとクイックアクセスの並べ替えはデータ書き換えとして保護バックアップを維持する。ProtectedBackupStorageのACL・所有者・再解析ポイント検証は、タスク登録用XML・移行保留情報にも適用し、危険な保存領域を検出した場合はfail closedにする。

クイックアクセスの並べ替えは、Shell名前空間を開けないピン留め（削除済みドライブ、アンインストール済みのクラウドドライブなど）を外さない。外すと付け直せず利用者のピン留めを失うため、元の相対順のまま先頭へ残し、開ける項目だけを昇順で付け直す。変更後の実状態検証は「残した項目＋並べ替えた項目」を期待値とし、残した項目があれば成功ではなく部分成功として対象パスを表示する。

## ファイル操作の境界

通常のファイル列挙・属性変更・削除・失敗時の属性復元は、再解析を拒否して取得した同一ハンドルを使う。`NativeCleanupEntry`が`NtCreateFile`の`OBJ_DONT_REPARSE`と最終要素の属性確認を集約し、ディレクトリの一覧もハンドルから取得する。パスを再解決して削除する代替経路へ戻さず、検証不能な対象は保持して診断へ含める。

クリーンアップの規則・SQLite・INI・実行中の製品・世代失効は[cleanup-design.md](cleanup-design.md)にまとめる。ファイル整理は通常のローカルドライブを対象とし、DOSドライブ名はデバイス名へ一度解決して操作中固定する。UNC・SUBSTなど安全な解決を実装していないマッピングは拒否する。起動時の再試行は保護キューを使い、名前だけを再解決する MoveFileEx 方式は使わない。

リンク保護は対象確認時点と削除直前のハンドル属性を基準とする。確認時点のリンクは保持し、途中でパスが差し替えられても同一ハンドルからリンク先へ作用しない。最終確認の後に別プロセスが同じオブジェクトをリンクへ変える競合については、リンク自身の残存までは原子的に保証しない。

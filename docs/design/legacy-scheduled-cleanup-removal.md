# 旧サインイン時クリーンアップの廃止と自己移行

[security.md](security.md) から分割した詳細。

サインイン時にクリーンアップを自動実行する機能は廃止した。タスクの登録・トグル・旧実行のコードはなく、`schtasks /create` による予約登録も持たない。旧版が登録した最高権限のタスク `\Lumin4ti\ScheduledTempCleanup` が残る環境では、`LegacyScheduledCleanupMigration`（COM の `Schedule.Service`）がそのタスクだけを取り除く。`ScheduledTaskExecutableTrust` は起動時再試行のタスクが使うので残す。

**削除条件**は次を全て満たすことで、削除直前に同じ COM オブジェクトで再照合する。

- Principal が現在の利用者（SID またはアカウント名）である。
- Action が単一の Exec である。
- Arguments が `--scheduled-cleanup-temp` と完全一致する。
- Command のファイル名が `Lumin4ti.UI.exe` である（旧 PerUser 配置も可）。

不一致や照会不能は保持してログへ残す。削除後に `\Lumin4ti` が隠しタスクを含めて空ならフォルダーも消す。`\Lumin4tiRebootCleanup` には触れない。保護ストレージの旧タスク用 XML（`scheduled-tasks` の `temp-cleanup-*.xml`）も削除する。

**契機は 2 つ**ある。

1. 昇格済み・単一起動確保後の通常起動。`MaintenanceOperationProcessLock` を取り、取れなければ次回へ持ち越す。失敗しても起動は続ける。
2. 旧タスクから `--scheduled-cleanup-temp` 付きで起動されたとき。Velopack より前の入口で、掃除は一切せず移行だけ試み、成否にかかわらず終了コード 0 で終わる。GUI・自己昇格・移行 MSI・Velopack へ流さない。

COM の同期呼び出しが応答しない場合に起動を止めないよう、どちらの契機も移行を別スレッドで実行し、全体の期限を 5 秒にする。期限切れでは共有ロックを手放し、取消を要求して残りの手順を行わず、ログへ残して次回へ持ち越す。

他の利用者が登録したタスクは消さない。その利用者の次回サインインで、契機 2 により自己削除される。非管理者で消せない場合も無害終了になる。Velopack のフックとアンインストールには入れない（SYSTEM 実行で所有者を照合できず、配布契約にも触れないため）。移行前にアンインストールした場合は、実体のないタスクが残りうる。

**撤去の条件**: COM による移行は 2027-11-30 まで残し、その後の撤去は本人の指示で行う。引数付き起動の無害終了は期限なしで残す。撤去すると、残存タスクがサインインのたびに昇格 GUI を開くためである。

# クリーンアップの安全ガードと固定ハンドラー

[cleanup-design.md](cleanup-design.md) から分割した詳細。

## カスタムフォルダー

中身だけを空にする。`settings.json` が非昇格でも書けるため、追加時と実行時の両方で `CustomFolderGuard` が検査する。次を拒否する。

- ドライブ直下、Windows・Program Files・ProgramData（自身・配下・祖先）
- 他の利用者のプロファイル、自分のプロファイル直下と AppData 系
- ブラウザー・メールのプロファイル基点とその祖先、パスに認証情報の名前を含むもの

許可したフォルダーの中でも、認証情報の拒否表に当たる名前の子孫は走査にも削除にも入れず残す。

## 実行中の製品

対象は同一セッション・同一利用者の範囲だけ。起動中の製品名を示して確認し、WM_CLOSE で最大 15 秒待つ。残った場合だけ、未保存の入力が失われることを示して再確認し、同意があれば開いたハンドルで SID と開始時刻を再照合してから終了する。強制終了できるのはブラウザーのキャッシュ・痕跡と Cookie の規則だけで、Explorer は対象にしない。拒否・失敗はその規則だけを `Skipped` にし、成功と表示しない。

## レジストリ・INI・SQLite

レジストリは HKCU の `Software\` 配下だけを、各階層をリンクとして開かずに確認して扱い、値の削除は同じハンドルで行う。INI は小さいファイルだけを、プロセス停止後に共有なしのハンドルへ書き戻す。

SQLite は NuGet を足さず、System32 の `winsqlite3.dll` を薄い P/Invoke で使う。固定の操作（Chromium の Cookie と autofill、Gecko の Cookie・フォーム履歴・ブックマークの無い履歴、指定表の全行削除）だけで、全祖先と DB を固定する。SQLite が名前で開く `-journal`・`-wal` も操作の終了まで 1 つのハンドルで固定し（`DatabaseSidecars`。再解析点・ハードリンク・中身のあるものは拒否）、DEFENSIVE・`trusted_schema=OFF`・トリガー無効で開く。期待する表・列と合わない、ロック中、整合性エラーの DB は無変更で `Partial` にする。除外した Cookie のドメインは本体とサブドメインを残す。Chromium の履歴はファイル規則で扱う。

## 固定ハンドラー

ごみ箱（Shell の API）、DNS キャッシュ（`SystemProcessResolver` 経由）、IE 系の履歴、ネットワーク使用量、無効なショートカット、無効なタスクは、データから名前だけを選ぶ C# の固定ハンドラーで扱う。無効なショートカットは MS-SHLLINK を独自に解析し、欠損が確定したものだけを削除する（PIDL のみ・広告型は保持）。無効なタスクは `\Microsoft\` 配下を除き、単一の実行ファイルの欠損が確定したものだけを対象にする。

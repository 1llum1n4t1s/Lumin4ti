# 高度なクリーンとスリム化

[cleanup-design.md](cleanup-design.md) から分割した詳細。

## 高度なクリーン

準備済みの固定ドライブをハンドル列挙し、リムーバブルは表示のみで既定未選択にする。Windows 全体・Program Files 系・ごみ箱・システム領域・他利用者のプロファイル・認証情報のフォルダー・`.git`・Lumin4ti 自身は枝刈りする。既定オンの拡張子と、追加（既定オフ）の拡張子・0 バイト・無効なショートカット・古いファイルを分け、判定が確かな「安全」、判定不能、利用者定義の区分で示す。24 時間以内に更新されたファイルと判定不能は未選択にする。結果は 5 列で並べ替えと仮想化ができ、表示上限を超えた分は超過を明示して削除しない。走査は MFT ではなくパス列挙で行う。

## スリム化と復元ポイント

スリム化は次を項目表で扱う。WinSxS は直接削除しない。

- 孤児 Installer（MSI API とレジストリの和集合に無い 30 日以上古い `.msi`・`.msp`）。列挙に失敗したら利用不可にし、実行直前に再照合する。
- 更新のロールバック・バックアップ・キャッシュ（DISM の公式手段と `SoftwareDistribution\Download`）、パッチキャッシュの残骸。
- 言語の入力補助機能（DISM の `Remove-Capability`。IME の本体は削除しない）、ヘルプ・既定の壁紙・サンプル。

`SfcIsFileProtected` が保護と答えるファイルと TrustedInstaller 所有のファイルは対象外で、Windows 10/11 ではヘルプ・既定の壁紙が通常 0 件になる。ロールバックの削除はアンインストールできなくなる警告と二段階確認を要する。

実行前に WMI の `SystemRestore.CreateRestorePoint` で復元ポイントを作る（既定オン）。前後の SequenceNumber で作成の省略を判定し、24 時間以内の既存点があれば日時付きで利用する。保護が無効・作成失敗のときは区別して示し、続行可否を確認する。頻度のレジストリは変更しない。復元ポイントは削除せず、管理は Windows の「システムの復元」に任せ、画面にはそれを開くボタンだけを置く。

## スタートアップと関連付け

スタートアップ登録とファイル関連付けの整理は、旧「その他」の専用アクション（`remove-broken-startup`・`remove-dead-associations`）を撤去し、「レジストリ」タブへ移した。旧アクションはバックアップなしで消していたため、移行後は判定を `StartupCommandParser` の確定欠損の基準で行い、バックアップを経て削除する。詳細は [registry-cleaner.md](registry-cleaner.md)。

## Defender の定義キャッシュ

信頼済みの最新 Platform 版 `MpCmdRun.exe` で `-RemoveDefinitions -DynamicSignatures`、続けて `-SignatureUpdate` を実行する。基本定義全体を巻き戻す `-All` は使わず、保護設定も変更しない。更新不要でも正常完了となるため、再ダウンロードしたとは断定しない。削除失敗時も更新確認は試し、一方でも失敗すれば全体を失敗とする。削除中のキャンセル後も独立したトークンで更新確認を試す。

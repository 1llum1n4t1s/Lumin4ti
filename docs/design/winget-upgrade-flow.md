# インストール済みアプリの更新（winget）

[workflow.md](workflow.md) から分割した詳細。

`WingetUpgradeAction`はwingetソースのexportがMicrosoft公式の既定設定と一致することを確認し、更新候補を一覧取得する。表が安全に解析できなければ全体を中止する。候補ごとに公式カタログを完全一致IDで照会し、1件のID一致、インストール済み表示名との整合性、Nightly・Betaなどの更新チャネル一致を確認してから、`--id --exact`で逐次更新する。IDだけではwingetの誤った紐付けによる別アプリ・別チャネルへの更新を防げないためである。名前の表記ゆれは許容するが、確認不能な候補は除外し、残りの候補を続行する。

各候補の成功・失敗・除外と終了コード（10進数・16進数）、標準出力・標準エラーの要約を結果、進捗、ログへ送る。出力から制御文字とANSIシーケンスを除き、意味のある末尾6行を抽出する。各行240文字、ストリーム要約600文字を超えた場合は切り詰めて省略記号を添える。インストール方式の不一致では発行元の公式インストーラーで更新方法を確認する案内を添える。

昇格側のwingetが終了コード`0x8A15007D`（ユーザースコープのportableを管理者コンテキストから操作できない）を返した候補だけ、同一利用者の非昇格wingetを1回だけ再試行する。他の終了コードや別の失敗は再試行しない。再試行を開始できなければその候補を失敗とし、通常権限のターミナルで同じ更新コマンドを実行するよう案内する。詳細は [unelevated-winget-retry.md](unelevated-winget-retry.md) を参照する。終了コード`0x8A150014`はwingetが自動更新の対象外と判断した候補であり、「自動更新の対象外」として別に集計し、失敗に数えない。

失敗・除外・対象外のすべてが0件なら`Success`、成功が1件以上、または失敗が0件なら`Partial`、それ以外は`Failed`を返す。安全上の除外・自動更新の対象外と更新失敗を別に集計することで、意図的に見送った候補を失敗と混同しない。

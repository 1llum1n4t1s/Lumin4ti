# 使用中キャッシュの起動時再試行

[workflow.md](workflow.md) から分割した詳細。

`RebootCacheCleanupService` は、画面のクリーンアップ（[cleanup-design.md](cleanup-design.md)）とは別の保護キューを扱う。`%ProgramData%\Lumin4ti\backups\reboot-cleanup-v1` に利用者 SID、固定5対象 ID、選択範囲と未処理範囲、世代・期限・試行結果を保存する。任意パスや SYSTEM の利用者設定を使わず、`RebootCleanupTargets` が ProfileList から元利用者の標準配置を再構成する。予約時に元対象と実際の設定保存先の標準配置・グローバル実体一致を検証できない場合は拒否する。新たな手動実行の選択が空でも、古い予約へその意図を反映する。起動時には正常読込できた現在設定の選択とも交差し、予約後に OFF にした対象を実行しない。

専用コンソール `Lumin4ti.RebootCleanup.exe` は Core だけを参照し、現在利用者の管理者権限と信頼済みインストールを確認してから動き、現在 SID の予約だけを扱う。UI、自己昇格、旧配置移行へ流れる経路を持たない。GUI と同じ自己完結ランタイムを共有して同梱し、既存の配布形式・署名方式を維持する。

SID 別固定タスク `\Lumin4tiRebootCleanup\CacheCleanup-{SID}` は専用フォルダーとタスクの所有者・ACL・定義を検証し、別所有者や未知の定義を変更しない。既存のマシン全体 lease を保持して再列挙・同一ハンドル削除を行い、FontCache のサービスは既存の停止確認と finally の復帰を使う。内部の取消期限で停止へ進み、サービス復帰中の強制終了を避けるため、タスクの実行期限は PT0S、AllowHardTerminate は false とする。BootTrigger に Explorer より前の完了保証はないため、表示は次回起動時の再試行とする。

処理前に試行を記録し、最大3実行・7日で終える。完了時は他利用者の予約も確認して自タスクだけを削除し、タスク自体にも期限後削除を設定する。ロック継続、失敗、期限到達等の結果は次の通常起動で現在利用者のログへ移す。既存の PendingFileRenameOperations は参照・変更しない。

起動処理は SYSTEM へ権限を拡大せず、同アカウントの新しいバッチログオンとして Windows のアクセス判定に従う。元の対話セッションのトークンと完全に同一とは保証しない。共有・ロック違反以外の拒否を含む対象は予約しない。S4U の登録・起動が許可されない環境では理由を記録して保持し、SYSTEM 実行へ切り替えない。

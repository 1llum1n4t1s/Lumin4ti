# 構成と設計判断

[DESIGN.md](../../DESIGN.md) から分割した詳細。

## 主要コンポーネント

| コンポーネント | 責務 | 主な境界 |
| --- | --- | --- |
| `Lumin4ti.Core` | メンテナンス項目、Windows操作、設定・ログ・バックアップ、外部プロセス管理 | UIを参照しない |
| `Lumin4ti.Core` の `Services/Windows/Cleanup/` | クリーンアップの規則データ・検証器、走査・削除、固定ハンドラー、レジストリ・INI・SQLite編集、高度なクリーン、スリム化、復元ポイント、設定 | 規則は埋め込みJSONだけ。UIを参照せず、画面は走査・実行・確認の境界を実装する |
| `Lumin4ti.UI` | Avalonia画面、MVVM、ローカライズ、DI、操作状態、更新UI | Coreの公開契約を呼び出す |
| `Lumin4ti.RebootCleanup` | 使用中キャッシュの起動時再試行の専用エントリポイント | Coreだけを参照し、現在SIDの保護キューを処理する。UI・自己昇格・旧配置移行を起動しない |
| `Lumin4ti.Tests` | 純粋ロジック、安全ガード、サービス補償、ViewModel、カタログ、配布契約の回帰検証 | レジストリ・デバイス操作はモック化し、ファイル削除はテスト専用一時領域で検証する |
| `scripts/verification/` | solution外のコンソールによる操作フロー検証 | 実ViewModelとCoreを使い、OS操作は模擬境界に限定する |
| `scripts/` のリリース処理 | publish、Velopack梱包、MSI補正、署名、R2公開 | リリース時だけ実行する |
| `../vps-web/deploy/lp-gateways/lumin4ti/` | 製品ページへ中継するCloudflare Worker | ページと共通CSS以外は既存のR2配信へ委譲する |

GUIと起動時再試行ヘルパーはそれぞれCoreに依存する。OS操作をUI層へ持ち込まず、CoreはAvalonia型を受け取らない。デバッグ画面と操作フロー検証は [debug-and-verification.md](debug-and-verification.md) にまとめる。

## ローカライズ

UI文字列は`src/Lumin4ti.UI/Resources/Locales/*.axaml`の17辞書で管理する。`en_US.axaml`が完全なキー集合で、英語以外の非日本語辞書は英語をmergeして上書きする。日本語辞書はシェル文言を中心に持ち、Action・カテゴリ・ステータスなどはコード内の日本語をフォールバックに使う。Coreは翻訳キーと日本語フォールバックだけを持ち、UIが現在言語を解決する。結果要約・保存診断・状態診断などは言語変更時に再評価し、OS例外の具体的な診断はそのまま保持する。

## 採用済み設計判断

| 判断 | 理由 | トレードオフ |
| --- | --- | --- |
| 巨大バッチではなくC#とWindows APIへ移植する | 入力、結果、キャンセル、復元、安全境界を型として検証できる | OS固有APIの実装とテスト用抽象化が増える |
| `asInvoker` manifestから自己昇格する | Velopack hookと旧版移行を昇格前に安全な順序で処理できる | 起動時にプロセスを再生成する必要がある |
| カタログ駆動でAction / BatchSetting / Toggle / Choiceを共通表示する | UI分岐を抑え、状態・結果処理を統一できる | 特殊機能も共通契約へ適合させる必要がある |
| 手動DIをSingletonで構成する | 単一Window・共有操作状態を単純に保てる | componentごとの短いlifetimeは使わない |
| 更新元とchannelをコードで固定する | 設定改ざんによる第三者ホストへの誘導を防ぐ | 任意mirrorへは切り替えられない |
| PerMachine MSIとSigiluneによるCI署名を採用する | 管理者ツールをユーザー書込み可能領域から実行せず、本人のPCなしで署名・配信できる | TOTP情報をEnvironment `release`のSecretsに置くため、読めるワークフローを増やさない |
| クリーンアップの対象を埋め込みJSONの規則とC#の固定ハンドラーに限る | 利用者が書ける定義を昇格プロセスが読まず、SQL・コマンドをデータに持たせない | 規則の追加にビルドとリリースが要る |
| 走査はパス列挙で行い、MFT列挙は使わない | リンク非追従と同一ハンドル削除をそのまま使える | MFT列挙ほどは速くない |
| SQLiteはSystem32の`winsqlite3.dll`をP/Invokeで使う | NuGetを足さず、配布契約に触れない | 古い版が新しいスキーマを開けなければ無変更で`Partial` |
| 削除は完全削除とし、所有権を奪わない | Shell削除は同一ハンドル削除を崩し、所有権の奪取は保護の迂回になる | 元に戻せないことを確認画面で示す。権限不足は`Partial` |
| サインイン時クリーンアップを廃止し、旧タスクを自己移行で除く | 昇格済みの無人実行経路をなくす | 他利用者の旧タスクはその利用者の次回サインインまで残る |

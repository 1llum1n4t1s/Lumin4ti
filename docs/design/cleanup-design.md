# クリーンアップと関連する整理操作

[security.md](security.md) から分割した詳細。

## 画面と構成

「クリーンアップ」は `CleanupView` が持つ 6 タブで構成する。

| タブ | 内容 |
| --- | --- |
| 通常 | 規則データから走査した項目を、分類別に件数とサイズ付きで選んで削除する。おすすめ・すべて選択・すべて解除、無視、場所を開く、テキスト書き出しがある |
| 高度 | 準備済みの固定ドライブを拡張子パターンで走査し、ファイル単位で選んで削除する |
| スリム化 | Installer の孤児、更新の残骸、言語の入力補助機能、ヘルプ・壁紙・サンプルを固定の項目表で扱う |
| レジストリ | 実体が消えた登録を、走査・カテゴリー別の選択・バックアップのうえで削除し、バックアップ一覧から復元する。動作が速くなるものではない。[registry-cleaner.md](registry-cleaner.md) |
| 設定 | 除外（ファイル・フォルダー・拡張子とファイル名・Cookie のドメイン）とそのインポート・エクスポート、カスタムフォルダー、安全な削除、復元ポイントの自動作成、累計と前回の実績 |
| その他 | 従来のカード（アイコン・サムネイル・フォントキャッシュ、検索インデックス、SSD の最適化。旧リンク切れスタートアップと旧関連付け候補はレジストリタブへ移した）。`CommandCategoryView` |

走査は lease を `showProcessing:false` で取り、画面内に進捗と中断を出す。削除は `showProcessing:true` で取る。走査・削除は起動時や再アクティブ時に自動で走らせない。旧版の予約実行・CLI・1 クリック起動はない。

## 共通の画面の型

通常・高度・スリム化・レジストリ・設定の各画面は、共通の入れ物 `CleanupPage`（`src/Lumin4ti.UI/Controls/CleanupPage.cs`）に載せる。テンプレートとスタイルは `src/Lumin4ti.UI/Styles/CleanupStyles.axaml`、色は `Resources/Themes.axaml` の `Brush.Danger*`・`Brush.Warning*`・`Brush.Success*` が持つ。「その他」だけは従来のカード表示。

- 領域は上から 見出し → 操作バー → 進捗 → 通知 → 結果カード → 本体 → 下端の実行バー。縦スクロールは本体の中の一覧だけが持ち、`CleanupPage` 自身は `ScrollViewer` で包まない。操作バー・通知・結果・実行バーは中身が無いとき余白も出さない。
- 確認は画面に重ねる確認シートで出す。開いている間は背面を操作不可にし、Esc で取り消す。ボタン行は下端に固定し、中身だけスクロールする。閉じたら開く前のフォーカスへ戻す。
- 常に見せるボタンは、走査（走査中は同じ場所が中止に替わる）と実行バーの削除だけ。選択の操作は「選択 ▾」のメニュー、使用頻度の低い操作と行ごとの操作は「⋯」のメニューへ入れる。
- 結果カードの色は、完全な成功のときだけ成功色。部分失敗・失効・取消は警告色、失敗は誤り色にする。実行後は結果の下に「実行したため、走査結果は使えなくなりました…」（`Cleanup.Ui.RescanAfterRun`）を出す。
- 状態の見せ方: 走査前は走査ボタンを強調し、本体に「まだ走査していません」の空状態を出して、通知の状態文は出さない。走査中は進捗を出し、走査ボタンが中止に替わる。0 件のときは通知の状態文で示す。走査結果が失効したときは通知に警告帯を出す。実行後は結果カードと上の再走査の案内を出し、走査結果の一覧は使えなくする。
- 内側のタブ見出しは横スクロールせず折り返す。高度は 7 列の表と最小幅の固定をやめ、2 行の行・種別の ComboBox・並べ替えメニューにした。レジストリはカテゴリーごとの入れ子スクロールをやめ、見出し行と項目行を 1 本の仮想化した一覧（`DisplayItems`）にした。

# クリーンアップと関連する整理操作

[security.md](security.md) から分割した詳細。

## 画面と構成

「クリーンアップ」は `CleanupView` が持つ 5 タブで構成する。

| タブ | 内容 |
| --- | --- |
| 通常 | 規則データから走査した項目を、分類別に件数とサイズ付きで選んで削除する。おすすめ・すべて選択・すべて解除、無視、場所を開く、テキスト書き出しがある |
| 高度 | 準備済みの固定ドライブを拡張子パターンで走査し、ファイル単位で選んで削除する |
| スリム化 | Installer の孤児、更新の残骸、言語の入力補助機能、ヘルプ・壁紙・サンプルを固定の項目表で扱う |
| 設定 | 除外（ファイル・フォルダー・拡張子とファイル名・Cookie のドメイン）とそのインポート・エクスポート、カスタムフォルダー、安全な削除、復元ポイントの自動作成、累計と前回の実績 |
| その他 | 従来のカード（アイコン・サムネイル・フォントキャッシュ、検索インデックス、リンク切れスタートアップ、関連付け候補、SSD の最適化）。`CommandCategoryView` |

走査は lease を `showProcessing:false` で取り、画面内に進捗と中断を出す。削除は `showProcessing:true` で取る。走査・削除は起動時や再アクティブ時に自動で走らせない。旧版の予約実行・CLI・1 クリック起動はない。

## 規則データ

通常クリーンの対象は `Lumin4ti.Core/Services/Windows/Cleanup/Definitions/*.json` の規則で、アセンブリへ埋め込む。外部ファイルの読み込み・更新経路は作らず、利用者が書ける定義を昇格プロセスが読むことはない。読み込みは source generator と `UnmappedMemberHandling.Disallow` で行う。

- 規則は分類（windows / storeApps / browserCache / browserTrace / cookies / traces / components / apps）、種別、影響度、検出条件、対象、実行中を確認するプロセス、停止するサービス、根拠を持つ。対象は `contents`・`files`・`registryValues`・`registryTree`・`sqlite`・`iniValues`・`handler` のいずれかで、SQL・コマンド・実行ファイルはデータに書かせない。
- 影響度は `junk`・`trace`・`signout`・`rebuild`・`userFiles`。再生成可能でサインアウトや履歴の喪失を伴わない `junk` だけが「おすすめ」になれる。Cookie とフォーム履歴は既定オフで、利用者が明示的に選んだときだけ削除する。受信ファイルなど再取得できない `userFiles` は「すべて選択」にも含めず、個別選択と専用の再確認を要する。保存パスワード・認証情報・鍵・アプリ設定は規則に入れない。
- 根拠は tier A（公式文書または製品の公開ソース）、tier B（独立した二次資料 2 件）、tier L（旧版が対象にしていた場所の継承）。どれも満たさない項目は収録しない。他社製品の設定ファイルを転記・変換せず、独自に裏付ける。
- ブラウザーは基点と種別（キャッシュ・履歴・フォーム・セッション・ブックマークの控え・Cookie）から規則を生成する（`CleanupEngineExpander`）。
- 検証器 (`CleanupRuleValidator`) は、id の一意性、許可された環境変数、絶対パス、基点直下の禁止、規則間の完全重複、認証情報の拒否表、registry の範囲、サービスの許可表をテストと起動時に確認し、違反した規則だけを無効にしてログへ残す。
- 表示名は製品名を翻訳せず、種別を書式キー（「{0} のキャッシュ」など）で組み立てる。Windows 項目は `Text.Cleanup.Rule.{id}` を持つ。

## 走査から削除まで

走査は何も変更せず、`FileCleanupScanner` が取得済みの列挙情報からサイズと各時刻を集計する。走査結果は世代番号を持ち、設定変更・削除開始・再走査で失効する。走査していない規則・対象は実行しない。

削除は `FileCleanupEngine` が、走査時と同じ規則・除外で再列挙して行い、走査完了時刻より後に作られたファイルは保持する。除外などで意図して残したものは `Retained` として数え、その親フォルダーの削除失敗は失敗にしない。高度なクリーン・孤児 Installer・無効ショートカットは、FileId・サイズ・更新時刻が走査時と一致する同一ハンドルだけを削除する。ごみ箱へは移さず完全削除とし、確認画面で元に戻せないことを示す。所有権の奪取や ACL の変更はせず、権限不足は件数と代表例を示して `Partial` にする。使用中で残る再起動後の削除は既存の固定 5 対象だけが対象で、任意パスの `MoveFileEx` 予約は作らない。

安全な削除（既定オフ）は同一ハンドルで 1 パス上書きしてから削除する。リンク数が 2 以上のファイル（パッケージマネージャーのハードリンク先など）、圧縮・スパース・EFS のファイルは上書きせず削除だけ行う。SSD では消去を保証しないと表示する。

規則どうしで対象が重なる場合（例: `%TEMP%` 全体と `%TEMP%\NeroSupport`）は、同じファイルを二重に数えず、二重に失敗にもしない。走査は先の規則が扱うファイルを重なりとして分け、選択の合計（`Measure`）は先の規則も選ばれているときだけ後の規則の分から引く。実行は先に処理した対象が扱ったものを飛ばす。固定ハンドラーが `Failed` を返した規則は、他の対象で消した件数にかかわらず `Failed` にする。

規則の基点の環境変数は `CleanupBaseTrust` で、OS が別経路で持つ値と照合してから使う。プロファイル系は既知フォルダーが HKLM の `ProfileList` と一致するプロファイルの内側だけを許し（`TEMP`・`TMP` は別ドライブも許すが、保護された場所・他人のプロファイル・ドライブ直下は拒否）、機械側は OS が示す既定の場所と一致するものだけを許す。確認できなければ規則を使わず、理由を表示する。

カスタムフォルダーは中身だけを空にし、`settings.json` が非昇格でも書けるため追加時と実行時の両方で `CustomFolderGuard` が検査する。ドライブ直下、Windows・Program Files・ProgramData（自身・配下・祖先）、他の利用者のプロファイル、自分のプロファイル直下と AppData 系、ブラウザー・メールのプロファイル基点とその祖先、パスに認証情報の名前を含むものを拒否する。許可したフォルダーの中でも、認証情報の拒否表に当たる名前の子孫は走査にも削除にも入れず残す。

画面へ返す理由・結果の文言は、辞書キーと引数を運ぶ符号（`CleanupMessage`）にして、UI が 17 言語の辞書から解決する。ログと書き出しは日本語へ戻す。

`CleanupOutcome` は削除・解放容量・削除不能・再起動時削除予約・安全上の除外を集計する。削除不能の代表例は最大 8 件のパスと理由を保持し、例外では HRESULT も含める。1 件が 1024 文字を超えた場合は切り詰めて省略記号を添える。

`CleanupSettings`（`settings.json` の `Cleanup`）は「外したもの」だけを保存し、更新で規則が増えても既存の選択が無効化されないようにする。旧 `CleanupExclusions` は読み込み時に 1 回だけ移行し、旧除外に当たる規則を外した状態にする。`CleanupExclusions` 自体は旧カードと旧版への戻しのため残す。

## 実行中の製品

実行中の製品は同一セッション・同一利用者の範囲だけを対象にする。起動中の製品名を示して確認し、WM_CLOSE で最大 15 秒待つ。残った場合だけ、未保存の入力が失われることを示して再確認し、同意があれば開いたハンドルで SID と開始時刻を再照合してから終了する。強制終了できるのはブラウザーのキャッシュ・痕跡と Cookie の規則だけで、Explorer は対象にしない。拒否・失敗はその規則だけを `Skipped` にし、成功と表示しない。

## レジストリ・INI・SQLite

レジストリは HKCU の `Software\` 配下だけを、各階層をリンクとして開かずに確認して扱い、値の削除は同じハンドルで行う。INI は小さいファイルだけを、プロセス停止後に共有なしのハンドルへ書き戻す。

SQLite は NuGet を足さず、System32 の `winsqlite3.dll` を薄い P/Invoke で使う。固定の操作（Chromium の Cookie と autofill、Gecko の Cookie・フォーム履歴・ブックマークの無い履歴、指定表の全行削除）だけで、全祖先と DB を固定し、SQLite が名前で開く `-journal`・`-wal` も操作の終了まで 1 つのハンドルで固定し（`DatabaseSidecars`。再解析点・ハードリンク・中身のあるものは拒否）、DEFENSIVE・`trusted_schema=OFF`・トリガー無効で開く。期待する表・列と合わない、ロック中、整合性エラーの DB は無変更で `Partial` にする。除外した Cookie のドメインは本体とサブドメインを残す。Chromium の履歴はファイル規則で扱う。

## 固定ハンドラー

ごみ箱（Shell の API）、DNS キャッシュ（`SystemProcessResolver` 経由）、IE 系の履歴、ネットワーク使用量、無効なショートカット、無効なタスクは、データから名前だけを選ぶ C# の固定ハンドラーで扱う。無効なショートカットは MS-SHLLINK を独自に解析し、欠損が確定したものだけを削除する（PIDL のみ・広告型は保持）。無効なタスクは `\Microsoft\` 配下を除き、単一の実行ファイルの欠損が確定したものだけを対象にする。

## 高度なクリーン

準備済みの固定ドライブをハンドル列挙し、リムーバブルは表示のみで既定未選択にする。Windows 全体・Program Files 系・ごみ箱・システム領域・他利用者のプロファイル・認証情報のフォルダー・`.git`・Lumin4ti 自身は枝刈りする。既定オンの拡張子と、追加（既定オフ）の拡張子・0 バイト・無効なショートカット・古いファイルを分け、判定が確かな「安全」、判定不能、利用者定義の区分で示す。24 時間以内に更新されたファイルと判定不能は未選択にする。結果は 5 列で並べ替えと仮想化ができ、表示上限を超えた分は超過を明示して削除しない。走査は MFT ではなくパス列挙で行う。

## スリム化と復元ポイント

スリム化は、孤児 Installer（MSI API とレジストリの和集合に無い 30 日以上古い `.msi`・`.msp`。列挙に失敗したら利用不可にし、実行直前に再照合する）、更新のロールバック・バックアップ・キャッシュ（DISM の公式手段と `SoftwareDistribution\Download`）、パッチキャッシュの残骸、言語の入力補助機能（DISM の `Remove-Capability`。IME の本体は削除しない）、ヘルプ・既定の壁紙・サンプルを項目表で扱う。WinSxS を直接削除しない。`SfcIsFileProtected` が保護と答えるファイルと TrustedInstaller 所有のファイルは対象外で、Windows 10/11 ではヘルプ・既定の壁紙が通常 0 件になる。ロールバックの削除はアンインストールできなくなる警告と二段階確認を要する。

実行前に WMI の `SystemRestore.CreateRestorePoint` で復元ポイントを作る（既定オン）。前後の SequenceNumber で作成の省略を判定し、24 時間以内の既存点があれば日時付きで利用する。保護が無効・作成失敗のときは区別して示し、続行可否を利用者に確認する。頻度のレジストリは変更しない。

Lumin4ti は復元ポイントを削除しない。復元ポイントの管理は Windows の「システムの復元」に任せ、画面には「システムの復元を開く」ボタンだけを置く。

## スタートアップと関連付け

スタートアップ登録とファイル関連付け候補はキャッシュ整理と混ぜず、「その他」の専用アクションでレジストリを整理する。`StartupCommandParser` が完全パスへ解決でき、準備済み固定ドライブ上で再解析点を通らない実行ファイルの欠損を確認できた候補だけを削除する。複数の関連付け候補の一つでも存在または判定不能なら保持し、レジストリアクセス不能は `Partial` として可視化する。

## Defender の定義キャッシュ

Defender の定義キャッシュ整理は、信頼済みの最新 Platform 版 `MpCmdRun.exe` で `-RemoveDefinitions -DynamicSignatures`、続けて `-SignatureUpdate` を実行する。基本定義全体を巻き戻す `-All` は使わず、保護設定も変更しない。更新不要でも正常完了となるため、画面では削除と更新確認の結果を示し、再ダウンロードしたとは断定しない。削除失敗時も更新確認は試し、一方でも失敗すれば全体を失敗とする。削除中のキャンセル後も独立したトークンで更新確認を試す。
